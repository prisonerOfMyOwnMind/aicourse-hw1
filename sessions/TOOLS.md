# Журнал инструментов

> Только дополняется, старые записи не редактируются. Сюда попадает всё, что вы
> добавили в проект или окружение ради этой задачи: библиотеки, CLI-утилиты,
> линтеры, MCP-серверы, плагины и скиллы агента, хуки, внешние сервисы, контейнеры.
>
> Разовый вызов уже установленного инструмента сюда не пишется — он идёт
> в таблицу инструментов внутри файла сессии.
>
> Тупиковая попытка — тоже запись: поставили, не подошло, сняли. Это как раз интересно.

## Шаблон записи

```markdown
## YYYY-MM-DD · Сессия N · <инструмент> vX.Y

- **Тип:** библиотека / CLI / MCP / плагин / скилл / хук / сервис
- **Установка:** `<точная команда>`
- **Зачем:** какую задачу решает
- **Область:** проект или глобально
- **Проверка:** чем убедились, что работает
```

Удалённый или заменённый инструмент фиксируется так же — с пометкой
**удалён** / **заменён на X** и причиной.

## 2026-08-17 · Сессия 1 · superpowers v6.3.0

- **Тип:** плагин Claude Code (набор скиллов)
- **Установка:** `claude plugin install superpowers@claude-plugins-official --scope project -y`
- **Зачем:** Spec-Driven Development — скилл `brainstorming` ведёт постановку задачи
  вопросами вместо того, чтобы модель писала спеку за владельца. Задание требует
  ровно этого: «отвечайте на его вопросы, а не пишите текст сами».
- **Область:** проект. Установлен именно в project scope, а не глобально:
  запись легла в `.claude/settings.json` внутри репозитория и уезжает вместе с ним.
- **Проверка:** `claude plugin list` в папке проекта показывает
  `superpowers@claude-plugins-official / Scope: project / Status: enabled`.
  Скилл `brainstorming` фактически отработал в этой же сессии — по нему собрана
  спецификация в `SPEC.md`.

## 2026-08-17 · Сессия 1 · ponytail v4.9.0

- **Тип:** плагин Claude Code (набор скиллов: `ponytail`, `ponytail-audit`,
  `ponytail-review`, `ponytail-debt`, `ponytail-gain`, `ponytail-help`)
- **Установка:** `claude plugin install ponytail@ponytail --scope project -y`
- **Зачем:** плагин форсирует самое простое работающее решение — YAGNI,
  стандартная библиотека вперёд, одна строка вместо пятидесяти. Главный риск
  этого проекта не в том, что игра не заработает, а в том, что агент навернёт
  архитектуру на задаче в несколько сотен строк.
- **Область:** проект.
- **Проверка:** `claude plugin list` показывает `ponytail@ponytail / Scope: project /
  Status: enabled`, версия 4.9.0. Скиллы на диске:
  `~/.claude/plugins/cache/ponytail/ponytail/4.9.0/skills/`.
  Фактическое влияние на поведение агента проверяется в следующей сессии —
  плагины, как и правила, подхватываются на старте сессии, а не в середине текущей.

## 2026-08-17 · Сессия 1 · маркетплейс ponytail, доработка конфига

- **Тип:** правка конфигурации проекта
- **Установка:** руками добавлен блок `extraKnownMarketplaces` в `.claude/settings.json`
- **Зачем:** `claude plugin install` записал в конфиг проекта только имя плагина
  `ponytail@ponytail`, а сам маркетплейс `DietrichGebert/ponytail` был известен
  только этой машине — он лежал в глобальном `~/.claude/settings.json`.
  На чистой машине проверяющего плагин не нашёлся бы, и репозиторий перестал бы
  подниматься строго по README. Теперь маркетплейс объявлен в самом репозитории.
- **Область:** проект.
- **Проверка:** `python3 -m json.tool .claude/settings.json` — валиден;
  `claude plugin list` в папке проекта видит оба плагина включёнными.
