# Сапёр под Android — домашнее задание после занятия 1

Учебный проект курса AICOURSE, направление Mobile. Смысл работы не в игре,
а в том, чтобы пройти рабочий цикл агента целиком: контекст, спецификация,
наивный прогон, работа по спеке, проверка, отчёт. Ход работы лежит
в `sessions/` и является частью сдачи наравне с кодом.

## Что это

Классический сапёр: два экрана, три уровня, партия переживает полное убийство
процесса. Kotlin, Jetpack Compose, Material 3, один модуль, **ни одной внешней
зависимости** сверх Compose: хранение — собственный текстовый формат в `filesDir`,
без Room, Hilt, Navigation и сериализаторов.

## Как запустить

Нужен JDK 21 и Android SDK. `ANDROID_HOME` должен указывать на SDK.

```bash
export ANDROID_HOME="$HOME/Library/Android/sdk"     # путь к вашему SDK
export PATH="$ANDROID_HOME/platform-tools:$PATH"

cd minesweeper

# тесты ядра игры — идут на JVM, устройство не нужно
./gradlew test

# сборка APK
./gradlew assembleDebug

# установка на подключённое устройство
./gradlew installDebug
```

APK появится в `minesweeper/app/build/outputs/apk/debug/app-debug.apk`.

### Если устройства нет

Готовый debug-APK лежит в `evidence/minesweeper-debug.apk` — его можно поставить
на любой эмулятор с API 26 и выше:

```bash
adb install evidence/minesweeper-debug.apk
adb shell am start -n dev.fedorfalchuk.minesweeper/.MainActivity
```

### Отдельно про Xiaomi

На MIUI установка по USB по умолчанию запрещена и падает с
`INSTALL_FAILED_USER_RESTRICTED`. Лечится включением «Установка через USB»
в параметрах разработчика. Это не ошибка сборки — APK при этом уже собран.

`compileSdk` подняли с 36 до 37 по ходу работы: свежие Compose и Lifecycle

## Что сделано

- Правила игры чистыми функциями, без единого импорта `android.*`
- Мины расставляются после первого тапа, минуя нажатую клетку и всех её соседей,
  поэтому первый ход всегда раскрывает область
- Раскрытие области итеративно; клетка с флажком волной не открывается
- Три уровня: 9×9/10, 12×12/20, 16×16/40 — плотность растёт по возрастанию
- Флажки долгим тапом, счётчик мин уходит в минус при перерасходе
- Таймер по монотонным меткам, а не тиками; в фоне стоит
- Сохранение партии и рекордов в отдельные файлы, атомарной записью,
  после любого изменения состояния, последовательно и вне главного потока
- Отказоустойчивое чтение: битый, обрезанный, чужой и рассогласованный файл
  трактуются как отсутствие файла, приложение не падает
- Оверлей исхода с кнопками «Заново» и «В меню», системная «Назад» уводит в меню
- Диалог подтверждения при выборе уровня поверх незавершённой партии
- Тёмная тема
- 56 unit-тестов на JVM

## Что не сделано и что упрощено

Честный список. Пункты отсюда не «забыты», а сознательно оставлены за границей.

- **Вибрация и анимация раскрытия волной.** Были в объёме, стояли последними
  в очереди после жизненного цикла и проверок. До них не дошли руки в отведённое
  время. Правила для них описаны в `SPEC.md` и реализуются первыми, если работа
  продолжится.
- **`minSdk 26` объявлен, но не проверен.** Устройство под рукой одно, на нём
  Android 13 (API 33). Эмулятор правилами проекта запрещён, системных образов
  в SDK нет. То, что приложение запускается на API 26, не проверялось ничем.
- **Цифры на поле не масштабируются системным шрифтом.** Их размер производен
  от размера клетки. Иначе на поле 16×16 при шрифте 200 % цифры вылезли бы
  за клетку. Системный масштаб уважает остальной интерфейс: таймер, счётчик,
  кнопки, рекорды.
- **Клетка меньше рекомендованной цели касания.** На экране 393dp клетка выходит
  41,0 / 30,5 / 22,6dp по уровням при рекомендованных Material 48dp. Поле обязано
  помещаться целиком без прокрутки; в сапёре это стандартный компромисс.
- **Нет аккорда** (тап по цифре с нужным числом флажков вокруг), звука, истории
  партий, статистики, экрана настроек, локализации кроме русского и отдельной
  альбомной вёрстки.
- **Нет UI-тестов.** Проверка интерфейса ручная, по чек-листу в `evidence/checklist.md`.

## Сравнение двух прогонов

Наивный прогон лежит в `naive/` и после фиксации не правился. Условия прогона
и отчёт агента дословно — в `naive/NAIVE-RUN.md`.

Один промпт: `напиши игру сапёр под андроид`. Пустая папка вне репозитория,
запуск с `--setting-sources ""`, то есть без правил проекта, без глобальных
правил машины и без плагинов. Модель та же — Opus 5. Отличалось только окружение.

### Что наивный прогон решил за меня

| Решение | Наивный прогон | Работа по спеке | Кто решал |
|---|---|---|---|
| Package | `com.example.minesweeper` | `dev.fedorfalchuk.minesweeper` | Шаблон против человека |
| minSdk | 24 | 26 | Молча против записанного в правилах |
| compileSdk / targetSdk | 34 / 34 | 37 / 36 | Молча против остановки с вопросом |
| Тулчейн | AGP 8.5.2, Kotlin 1.9.24 | AGP 9.2.1, Kotlin 2.4.0 | Взято из головы против взятого из кэша и Google Maven |
| Уровни | 9×9/10, 16×16/40, 16×30/99 | 9×9/10, 12×12/20, 16×16/40 | Классика против осознанного выбора плотности |
| Хранение | `SharedPreferences` | Файлы с версией формата и атомарной записью | Умолчание против требования |
| Что переживает перезапуск | Только рекорд | Партия целиком, флажки, накопленное время | — |
| Тесты | 15, ни разу не запущены | 56, прогнаны с показанным выводом | — |
| Сборка | Ни разу | Собрана, установлена | — |
| Gradle wrapper | Отсутствует | На месте | — |

### Главное расхождение

Наивный прогон отчитался: «поворот экрана без потери партии». Это правда.
Но **сохранения партии на диск в нём нет вообще** — в `SharedPreferences`
пишется единственное значение, лучшее время. Убийство процесса уносит партию
целиком.

Для задания Mobile это центральное требование: «данные переживают полный
перезапуск — не сворачивание, а убитый процесс». Наивный прогон его не выполняет
и в отчёте об этом не говорит: формулировка составлена так, что звучит как
сохранение состояния.

Это и есть цена работы без спецификации. Не «код хуже» — код как раз приличный,
1136 строк, чистые функции правил, отдельный слой UI. Хуже другое: продукт
не делает главного, а отчёт выглядит так, будто делает.

### Где наивный прогон оказался лучше

Честности ради. Он сделал **аккорд** (тап по открытой цифре с нужным числом
флажков вокруг), **переключатель режима флажка** в дополнение к долгому тапу
и **`contentDescription` на клетках для TalkBack** — ничего из этого в работе
по спеке нет: первые два отклонены сознательно, доступность в спеке не значилась
вовсе и всплыла только при сравнении.

И он был быстрее: один промпт против часов обсуждения, ревью и правок.
